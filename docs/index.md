# AI Development Practice Guide for Students

This guide was created for students enrolled in the **System Design** course.

Learn to define a specification, review changes, and verify behavior while using AI for assistance. Start with whichever of Antigravity, Grok Build, GitHub Copilot, Codex, or Claude Code fits your access and budget. You do not need subscriptions to all five.

!!! info "When product terms were checked"
    October 6, 2026. Prices, student benefits, usage limits, and interfaces can change. Before subscribing, review [Costs and student benefits](plans.md) and its official sources. The English translation was prepared on October 13, 2026; the product terms have not been rechecked as part of translation.

## What you will learn

| Stage | What you check yourself | What you keep |
| --- | --- | --- |
| Setup | Official distribution source and correct account | Environment and subscription notes |
| First run | Reading, editing, and execution work | A small smoke check |
| Specification | Inputs, outputs, and completion criteria | SPEC.md |
| Implementation | Changes match the specification | Code and diffs |
| Verification | Normal, boundary, and invalid inputs behave correctly | Tests and VERIFICATION.md |
| Handoff | Work can be reproduced and resumed elsewhere | ENVIRONMENT.md and HANDOFF.md |

Chat history alone does not provide a complete set of working code and verification evidence. **Keep the specification, code, and verification records in the same project so you and the next AI tool can read them again.**

## Reading order

1. Choose an accessible tool using [Costs and student benefits](plans.md).
2. Prepare your folder and records using [Common setup](setup.md).
3. Follow the tool's setup page and complete the first-run checks.
4. Work through specification, implementation, and verification in the [Practice project](practice.md).
5. Move to another conversation or tool using [Handoffs between environments](workflow/handoff.md).

If you are new to programming or terminals, begin by recording errors and actual results. The Python example is for learning. The same workflow applies to web apps, research scripts, and personal projects.

## Your first completion goals

- [ ] Explain your plan and additional billing settings.
- [ ] Know which folders, commands, and network operations are allowed.
- [ ] Run tests derived from acceptance criteria.
- [ ] Resume work in another conversation by rereading the project files.
- [ ] Explain the reasons for AI-generated changes in your own words.

When submitting work, follow the recipient's AI-use policy. Record which tools you used, what you delegated, and what you verified yourself.
